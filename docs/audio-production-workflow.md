# Ohana audiobook production — Hex / Dex handoff

Status: approved workflow direction; implementation and acceptance tests pending.
Scope: begin with Elsewhere (2026 Reboot) Episode 2; keep original Elsewhere, Hidden Valley, existing published episodes, player and music library unchanged.

## Responsibilities
- Hex: manuscript and story continuity, cast and voice direction, HeyGen recording, illustrations; supply corrected takes when QA flags a defect.
- Dex: build and maintain reusable audio tooling; validate recordings against the script, assemble dialogue, mix atmosphere and effects, produce previews and quality reports, verify release.
- Ninja: creative approval of story, voices, atmosphere and preview. Do not require Ninja to find technical defects. Publishing requires explicit approval of the identified master.

## Input contract
Use an immutable script revision and structured cue manifest. Each cue has stable cue ID, scene, order, speaker, exact spoken text, voice ID, role (narration/dialogue/thought), gain, source take ID, source asset locator, duration and checksum. Keep all takes immutable; mark superseded takes rejected rather than overwriting them. Never silently alter script words, speaker, pitch or speed. Keep secrets, credentials and expiring signed URLs out of public logs and commits.

Current voice defaults: Wade (a3a4aa242aaf431ea8ec2c4b3bb332fa), Hallie (8f71d16d1fa84544a4db41a18264d613), original pitch and speed 1.0; Hallie dialogue 0.90 linear gain, Ninja thoughts 0.80, Hex thoughts 0.80. Preserve the established per-episode cast for other speakers. Apply gains once only (0.90 is about -0.915 dB, not -10 dB). Use complete natural speaking turns or paragraphs per voice, within HeyGen limits. Very short isolated utterances require special QA; do not synthesize filler words into the final script.

## Required stages
1. Freeze manuscript and manifest, validate unique IDs, speaker mapping, order and expected text; ensure every cue has exactly one approved take.
2. Ingest source WAVs (or native source format), retain lossless intermediate audio at a consistent sample rate/channel layout. Check decodability, duration, silence, clipping, suspicious abrupt starts/ends, missing words and repeats. Run per-take ASR against expected text with conservative normalization (case, punctuation, equivalent numerals); keep raw text and timing. Short clips, low confidence, proper names and disagreements must be reviewed; a blank ASR result is not a pass. Cross-check flagged clips in context and with a second ASR when useful. Intentional repetitions in script must remain. Reject unapproved extras or omissions. Request only necessary pickups from Hex. Never auto-retry paid generation after an error or silently switch accounts.
3. Assemble dialogue from approved complete takes, preserving natural pitch/speed and complete words. Set context-sensitive gaps, especially on speaker changes; avoid overlaps, mid-word cuts, abrupt ends, double gain and automatic time stretching. Any trim of a duplicate complete utterance must be bounded by verified silence and separately approved; prefer a clean new take. Produce dry voice master and cue timeline with exact sample offsets.
4. Build independent environment and foley/effects stems from scene cue IDs, not hardcoded absolute timestamps. Preserve stems and project configuration so a pickup can replace one cue and deterministically regenerate timing/mix without altering unrelated recordings. No intelligible background voices, copyrighted music without permission, or unapproved processing. Maintain intelligibility and headroom; measure clipping, peak and loudness. Deliver lossless stems and one final MP3.
5. QA assembled dry voice and final mix in chapter-sized segments (within ASR limits), comparing against complete manuscript in order, including end-of-segment words. Check missing/extra words, duplicated cues, overlaps, gaps, clipping, abrupt cuts and transitions. Report exact episode timestamp, cue ID, expected/actual text, failure, severity and disposition. Automated ASR is not proof of naturalness: require listening review of flagged passages and representative joins, ideally the complete master; if human listening unavailable, explicitly state that limitation. Export short scene previews and a full preview with unique version/hash. No publish on unresolved critical flags or missing approval.
6. Release: stage on a separate working branch, do not merge unrelated changes. On explicit approval of exact master checksum, copy only needed assets into main and update only the intended reboot episode's audio/metadata/catalog entry atomically; preserve text, illustrations, original series, all other features. Verify main blob matches approved preview, catalog path exists, correct episode/series ID, public URL and Ohana readback agree. Use a new filename for each release; don't report success until verified. If player is stale, diagnose cache/version and do not delete a previous asset until no current catalog references it and owner approves deletion. Keep rollback manifest and prior version history. Never rewrite Git history.

## Deliverables for Dex
- Reusable CLI/scripts and CI workflow(s) for manifest validation, raw ASR QA, deterministic mixing, final QA and explicit release; configurable ASR adapter (local Whisper/faster-whisper or supported service) with no embedded secrets.
- Example cue manifest, example soundscape configuration, clear run instructions, machine-readable QA report plus human-readable summary, immutable input/output hashes and versioned preview.
- Tests using synthetic fixtures (no paid TTS needed) and a regression fixture from Episode 1; work in a feature branch and open a PR. Do not modify live episode assets or Ohana player as part of implementing the pipeline.
- Manual review/approval record tied to SHA and documented failure recovery; missing artifacts, uncertain ASR, unexpected repeats, wrong episode ID, stale catalog, and publication verification failure must never silently pass.
- Keep cost and disk usage modest; cache approved source takes and QA by content hash, but never treat stale cache as a new verified result. No background processing promises; report actual run state and outputs.
